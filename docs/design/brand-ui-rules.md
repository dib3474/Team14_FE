# FestaPick 독립 UI 디자인 규칙

원본 develop에서 만든 밝은 오렌지·블루 개선안의 실제 구현 규칙이다. 이전 feature/mobile-design의 아이보리·초록 안과 별도로 관리한다. [구현 명세](brand-ui-spec.md), [비교·검증 보고서](brand-ui-comparison.md), [전체 수정 파일](brand-ui-files.md)을 함께 본다.

## 원칙과 적용 범위

기능 보존 → 가독성 → 일관성 → 반응형 사용성 → 시각적 완성도 순으로 판단한다. 기존 로고·주황색 Primary·파란색 Secondary·지역 지도·캐릭터를 재사용한다. 같은 역할은 공통 토큰과 컴포넌트로 표현하고, 다른 역할까지 숫자만 같다는 이유로 합치지 않는다. API·인증·라우터·업무 훅을 스타일 수정에 섞지 않는다.

## 색상과 표면

값의 기준은 [index.css](../../src/styles/index.css)다. 기존 primary/secondary20개 값은 그대로다.

| 역할                        | 사용 규칙                                                                                                                   |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Primary                     | 기존 오렌지 배경과 선택 강조. 작은 강조 글자는 primary-700, 오렌지 버튼 위 글자는 primary-900을 사용한다.                   |
| Secondary                   | 보조 행동·설명·포커스에 블루를 사용한다. secondary-50 배경과 secondary-700 글자를 기본 조합으로 쓴다.                       |
| ui-canvas / ui-surface      | 블루그레이 페이지 바탕과 흰 정보 표면을 구분한다.                                                                           |
| ui-ink / ui-muted / ui-line | 주요 글자·보조 설명·얕은 구분선 역할이다.                                                                                   |
| ui-panel / ui-inset         | 큰 정보 구역과 그 안의 보조 카드. 20px/14px 둥글기, 1px 구분선을 사용한다.                                                  |
| 상태                        | 선택은 색 외에 pressed/current·체크 표시·굵기 등을 함께 사용한다. 오류는 읽을 수 있는 붉은 글자와 연결된 설명으로 표시한다. |

강한 그림자·확대 hover·두꺼운 선택 테두리를 일반 카드에 반복하지 않는다. [Button](../../src/components/common/Button.tsx)의 primary/secondary/tertiary와 기존 size/fullWidth/disabled API를 사용한다. 기본 높이는48px, 작은/아이콘 버튼도44px 이상을 우선한다. 링크는 이동, 버튼은 실행에 사용하고 중첩하지 않는다. 일반 포커스는 Secondary outline, 입력 포커스는 Primary 계열로 제공한다. 동작 감소 선호도 전역에서 처리한다.

## 글자·간격·반응형

- ui-title24px, ui-section-title18px, ui-body14px, ui-caption12px가 기본 역할이다. 본문은 충분한 행간과 긴 한글/주소 줄바꿈을 사용한다.
- 기본 여백20px, 359px 이하16px다. 구역 간24px, 카드 내부20px, 보조 카드16px를 공통 기준으로 쓴다.
- 앱 최대 폭480px, 헤더56px, 하단 메뉴72px와 Safe Area는 ui-\* 변수로 관리한다. 헤더 제목은 같은 너비의 좌우 영역 사이에 둔다.
- 화면 전체가 옆으로 넘치지 않게 min-width:0·줄바꿈을 사용한다. 원래의 이미지 갤러리·목록 내부 가로 탐색은 유지한다.
- 큰 화면에서 앱을 무조건 늘리지 않는다. [Container](../../src/components/common/Container.tsx), [Header](../../src/components/common/Header.tsx), [Footer](../../src/components/common/Footer.tsx), 상세 하단 행동이 공통 폭을 사용한다.
- Footer 선택은 현재 경로에서 파생한다. 호환용 initialSelected는 경로를 분류할 수 없는 경우에만 보조 기준이 된다.

## 입력·모달·비동기 상태

[OutlineInputField](../../src/components/form/OutlineInputField.tsx)는 ui-control을 사용하며 기존 rounded 옵션과 native props를 보존한다. aria-invalid와 aria-describedby로 오류·기존 도움말을 연결한다. [TextInputWithCounter](../../src/components/form/TextInputWithCounter.tsx)는 같은 입력 기반의 filled 변형이며 name을 id로 연결하고 글자수를 설명으로 제공한다. 기존 최소 길이 표시 시점과 검증 로직은 유지했다. 날짜는 시작일/종료일을 각각 이름 붙이고 좁은 화면에서 세로로 배치한다.

```tsx
<label htmlFor="department">소속</label>
<TextInputWithCounter
  name="department"
  value={department}
  onChange={handleChange}
  placeholder="소속을 입력하세요"
  maxLength={50}
/>
```

확인·프로필·미디어 모달은 [useDialogFocus](../../src/components/modal/useDialogFocus.ts)를 공유한다. 닫힐 때 호출 위치로 돌아가고, Escape·Tab·스크롤 잠금을 처리한다. 숨김/비활성 제어는 순환에서 제외한다. 업로드 중 제어가 모두 비활성화되면 tabindex=-1인 dialog에 초점을 두며, 성공 화면의 새 제어가 나타나면 내부 초점을 복구한다. 지역 모달은 원래 두 목적지와 방언·캐릭터를 보존하는 named dialog다.

구역 로딩·빈 결과·오류는 공통 LoadingSpinner/EmptyComponent/ErrorComponent를 사용한다. 실제 실패의 범위와 가능한 재시도를 표시한다. 이미 존재하던 API 집계·로딩 경계·에러 흐름을 임의로 바꾸지는 않았다. 검색 입력은 로딩/오류 중에도 같은 요소를 유지한다.

## 화면별 조합과 예외

| 화면         | 적용 규칙                                                                                                                                                                                                                                                            |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 홈           | 자연스러운 세로 흐름, 밝은 블루 지도 패널, 기존480/467 stage와 같은 좌표층. 지역 캐릭터40px와 원본 핀 좌표·목적지를 유지한다. 359px 이하에서는 겹침 방지를 위해 핀 hitbox만32px로 두며 동일 동작의44px 지역 이름 버튼을 함께 제공한다.                               |
| 목록·검색    | 포스터 중심 세로 카드. 제목·전체 주소·기간·평점·관심을 차례로 읽고 AI 배지를 구분한다. 원본의 진행 판정·디바운스·필터·페이지 조회는 그대로다.                                                                                                                        |
| 상세·공지    | 포스터 전체 비율을 유지하고 정보·공식 링크/관심·소개·공지·리뷰·관리를 공통 표면으로 나눈다. 갤러리 선택점은44px 제어와 작은 표시점을 분리하며 이름/pressed를 제공한다. 비활성 공지는 inert 처리한다. 리뷰 미디어와 공지 축제 요약은 키보드로도 기존 행동을 실행한다. |
| AI PICK·내역 | 기존 선택/MBTI/요청을 유지하며 단계·선택 개수·pressed·체크 표시를 제공한다. 스타일은 최근3개를 유지하는 기존 Provider 동작을 그대로 쓴다. 포스터·선택 요약·추천 카드의 메타 정보를 감추지 않는다.                                                                    |
| My·설정      | 같은 탭·표면과 왼쪽 정렬 메뉴 행·구분선·상태 역할을 쓴다. 권한·삭제·신청·업로드 조건은 유지한다.                                                                                                                                                                     |
| 채팅         | 원래 전송/정렬/255자 제한을 유지한다. 메시지는 남은 영역에서 스크롤하고 입력은 아래에 둔다. 입력에 초점이 있는 동안만 visualViewport를 반영하며 listener/frame을 정리한다. API에 없는 시간을 만들어 표시하지 않는다.                                                 |
| 로그인       | 원래 로고와 소셜 버튼/URL/문구를 유지하고 큰 워드마크·여백·버튼 배치를 작은 화면에 맞춘다.                                                                                                                                                                           |

## 검증과 재사용

새 화면은 ui-page와 ui-panel을 조합하고, 공통 변경은 실제 소비 화면까지 확인한다. 새 UI 라이브러리를 추가하지 않았다. 시각 규칙은 실제 렌더와 접근성 진단, 행동 변경은 회귀 테스트로 확인한다. 클래스 문자열을 복사한 테스트로 디자인 품질을 대체하지 않는다. [비교 도구](../../scripts/design-comparison/README.md)의 mock 인증/소켓/검색 초기화는 생성된 로컬 설정에서만 사용하고 제품 빌드에는 포함하지 않는다.

자동 점수는 실기기·WCAG 전체·실제 OAuth/S3/STOMP 인증이 아니다. 검증하지 않은 화면/환경은 [보고서의 제약](brand-ui-comparison.md)에 남긴다.

## 공통 말풍선 사용 규칙

[SpeechBubble](../../src/components/common/SpeechBubble.tsx)은 채팅에서 사용하던16px radius, 본문14px, 상대방의 흰 표면·선·작은 왼쪽 상단 모서리, 내 메시지의 Primary100·작은 오른쪽 상단 모서리를 공유한다. 기본값은 기존 채팅 모양이다. 짧은 지역명 안내에는 꼬리 없이 모든 모서리가 둥근 compact 형태를 선택하고, 버튼 안에서는 as="span"을 사용한다. 화면마다 말풍선 스타일을 복사하지 않는다.

지도 위 자동 안내는 캐릭터 모션과 같은 지연·주기를 사용한다. 사용자가 호버하거나 키보드로 탐색하면 자동 순환을 멈추고 해당 지역을 보여 준다. 모션 끄기·동작 줄이기 설정에서도 수동 지역명 확인은 가능하게 유지한다. 위치 안내를 위해 원본 지역 좌표나 hitbox를 이동하지 않는다.
