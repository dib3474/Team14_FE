## 날짜와 조회 규칙

선택한 기간과 축제 기간이 하루라도 겹치면 포함한다. 양 끝은 포함하며 한쪽 날짜만 선택해도 된다. 진행 중은 사용자의 로컬 날짜 기준 시작일≤오늘≤종료일이다. 잘못된 날짜/역전 범위에는 오류 설명을 제공하고 날짜 조건을 적용하지 않는다.

현재 API는 날짜 인자를 지원하지 않는다. 검색에는 keyword/page/size, 지역 목록에는 기존 area/current/page/size만 전송한다. 날짜 조건이 있으면 필요한 나머지 페이지를 클라이언트에서 확인한다. 검색의 진행 중 조건도 클라이언트 조건이므로 뒤 페이지까지 읽는다. 범위가 크면 요청 수가 증가하는 비용이 있으며, 향후 서버 날짜 검색이 지원되면 이를 내려보낼 수 있다.

스캔 중에는 확정적인 빈 결과를 표시하지 않는다. 일부 실패 시 앞서 받은 결과를 유지하고 수동 재시도로 이어간다. 지역 첫 요청 실패도 필터/지역 이동을 유지하고 같은 쿼리를 다시 요청한다. 초기화는 필터 키만 지워 다른 쿼리를 보존한다. [공통 필터](../../src/components/festival/FestivalFilters.tsx), [날짜 규칙](../../src/utils/festivalFilters.ts), [검색 훅](../../src/hooks/useSearch.ts)을 기준으로 한다.

## 내 리뷰와 프로필

[내 리뷰 미리보기](../../src/pages/My/components/MyPageOwnReviewPreviews.tsx)는 기존 getMyReviews를 호출한다. 제목이 같아도 축제 ID를 추정해서 연결하지 않고 리뷰 ID로 수정 화면을 연다. `myReviews/preview/5` 캐시를 분리하고 기존 myReviews 무효화 prefix를 유지한다. staleTime0으로 작성/수정 후 돌아왔을 때 새 내용을 읽는다. `?tab=reviewed`로 리뷰 탭을 직접 열고 수정 후 뒤로 가도 같은 탭을 유지한다.

프로필 모달·업로드·권한·로그아웃·탈퇴 핸들러는 원래 동작을 유지한다. 목 앱의 변경 요청은 읽기 전용 안내를 반환하며 실제 OAuth·저장·업로드·STOMP 전송은 하지 않는다. 일반 사용 앱의 인증 경계와 목의 샘플 계정을 구분한다.

## 2026-11-15 홈 선택·검색 여백 보완

홈은 ‘설레는 축제 여행’ 제목과 ‘지도 속 지역 픽픽이를 누르고 취향에 맞는 축제를 만나보세요.’ 안내 하나를 사용한다. 기존 상단 eyebrow·‘나의 다음 픽은?’·별도 하단 안내는 제거했다. 같은 패널의 지도/이름 버튼으로 선택 방식을 전환하며 보이지 않는 쪽은 unmount한다. 두 방식은 같은 지역 ID·모달·목적지를 사용하고 모드 전환 버튼의 초점을 유지한다.

17개 지역 캐릭터는1.2초 간격으로 차례로 커진다(전체20.4초). 이미지에만 transform을 적용해 상대 좌표와 클릭 크기는 유지한다. hover/키보드 초점/지역 모달 중에는 자동 모션을 멈추며 사용자가 끌 수 있다. 지도/이름을 왕복해도 모션 설정을 유지한다. prefers-reduced-motion에서는 애니메이션을 없애고 동작하지 않는 모션 제어를 숨긴다. CSS만 사용하므로 순환용 JS timer나 매 프레임 React 상태 갱신은 없다.

검색의 외부 패딩은 원래 설정과 같은24px/20px였다. 검색 입력에만 겹치던 추가 top margin8px를 제거해 intro의 공통12px 간격을 사용한다. 빈 결과 카드의 별도 상하 패딩도 제거해 공통 패널 기준을 따른다. 좌우 페이지 여백은 공통 ui-gutter를 유지한다.

신규 동작3개는 RED→GREEN, 기존 지역 이동·모달·Footer 동작을 포함해 전체181개/25파일이 통과했다. 타입·린트·빌드도 통과했고 큰 스냅샷 경고2건과 기존 번들 경고는 남아 있다. 독립 소스 리뷰는 No Issues이며 리뷰어가 실제 브라우저를 재실행한 것은 아니다. 작성자가375px 기본 모션·320px 동작 감소·375px 검색, 실제 토글 후 DOM의320px 이름 레이아웃을 Headless Chrome으로 확인했다. 네 진단의 접근성은100점·페이지 가로 넘침은0이었다. 실제 브라우저 클릭 E2E나 실기기 인증과 구분한다.

[검증 JSON](../metrics/2026-11-15-home-search.json)에 계산된 여백·애니메이션 이름/지연·원시 해시를 기록했다. 비교 페이지의 홈·검색 PNG는 최신 상태로 갱신하며, 이번 진단 원본은 날짜/해시별 로컬 verification 폴더에도 따로 보존했다. API·라우터·인증·지역 좌표·이미지 원본은 변경하지 않았다.

## 2026-11-15 홈 제어와 지역 말풍선 보완

제목과 안내 문장 사이 gap을12px에서0px로 줄였다. 지도 패널의 제어 순서는 모션→지도→이름이며, 세 버튼 모두44×44px·12px radius로 맞췄다. 토글 바깥 프레임의 추가 여백을 없애 선택 배경과 pressed 상태로 구분한다.

지역명은 캐릭터 위 말풍선으로 표시한다. 호버·키보드 초점에서는 해당 지역만 보이고, 자동 순차 모션에서는 같은 지연과 주기로 캐릭터 확대와 이름을 동기화한다. 활성 핀의 층을 높여 주변 캐릭터에 이름이 가리지 않게 했다. 모션 끄기와 prefers-reduced-motion은 자동 이름 안내도 중지하며 수동 호버·초점 안내는 유지한다. 이름은 기존 버튼의 접근성 이름과 같아 장식적 중복 텍스트는 aria-hidden 처리한다.

채팅의 실제 텍스트 말풍선을 공통 SpeechBubble로 추출했다. 채팅은 기존 HTML·클래스·색상·간격을 그대로 사용하고, 홈만 compact 크기와 아래 꼬리를 선택한다. 메시지 처리·전송·지역 좌표·핀 hitbox·모달·이동 목적지는 그대로다.

전체183개/25파일 테스트, typecheck·lint·build 통과. 린트의 기존 스냅샷 경고2건과 기존 번들 크기 경고는 남아 있다.375px 기본 모션과320px 동작 감소를 실제 Headless Chrome으로 렌더링했다. 제목 다음 문장이 바로 이어지고, 모든 표시 제어는44px이며, 가로 넘침0·Lighthouse 접근성100점을 확인했다.320px 동작 감소에서는 자동 애니메이션이0개다. 독립 소스 리뷰는 중요 문제 없음이다. 호버·키보드의 실제 브라우저 조작 E2E는 수행하지 않았으며, JSDOM 동작 테스트와 CSS 소스 리뷰로 보완했다. 비교 홈 캡처에서 자동 지역 말풍선의 표시도 확인했다.

[검증 수치](../metrics/2026-11-15-home-bubbles.json)와 해시별 로컬 원본을 보존하고 비교 화면의 홈 PNG를 갱신했다. 이 접근성 점수는 로컬 목 홈 화면 진단이며 성능 점수나 전체 서비스 접근성을 의미하지 않는다.
