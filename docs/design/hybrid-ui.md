# 선택한 FestaPick 최종 조합안

사용자가 선택한9개 조합을 `feature/hybrid-ui`에서 반영했다. 출발점은 독립안5617c2c이며 독립안 브랜치와 이전36ff3e2는 보존한다. 기존 [독립안 보고서](brand-ui-comparison.md)는 당시 기록으로 남긴다.

## 실행·비교

- 실제 개발 목 앱: http://127.0.0.1:5184/
- 내 리뷰 바로보기: http://127.0.0.1:5184/mypage?tab=reviewed
- 비교 화면: http://127.0.0.1:5182/superpowers/comparison/index.html
- 원본5180 / 이전안5181 / 최종 조합안5182 / 순수 독립안5183을 별도 서버로 실행한다. 비교 페이지의 체크박스로 원본과 독립안을 추가한다.

```sh
npm run dev:mock -- --host 127.0.0.1 --port 5184 --strictPort
node scripts/design-comparison/prepare.mjs
node scripts/design-comparison/start.mjs
```

비교 설정은 같은4개 고정 데이터를 사용한다. 일반 목 앱은16개 지역×진행 중/예정/종료의48개 샘플과 계정·리뷰·관리 데이터를 제공한다. [비교 도구 안내](../../scripts/design-comparison/README.md)에 실행·종료·캡처 방법을 정리했다.

## 날짜와 조회 규칙

선택한 기간과 축제 기간이 하루라도 겹치면 포함한다. 양 끝은 포함하며 한쪽 날짜만 선택해도 된다. 진행 중은 사용자의 로컬 날짜 기준 시작일≤오늘≤종료일이다. 잘못된 날짜/역전 범위에는 오류 설명을 제공하고 날짜 조건을 적용하지 않는다.

현재 API는 날짜 인자를 지원하지 않는다. 검색에는 keyword/page/size, 지역 목록에는 기존 area/current/page/size만 전송한다. 날짜 조건이 있으면 필요한 나머지 페이지를 클라이언트에서 확인한다. 검색의 진행 중 조건도 클라이언트 조건이므로 뒤 페이지까지 읽는다. 범위가 크면 요청 수가 증가하는 비용이 있으며, 향후 서버 날짜 검색이 지원되면 이를 내려보낼 수 있다.

스캔 중에는 확정적인 빈 결과를 표시하지 않는다. 일부 실패 시 앞서 받은 결과를 유지하고 수동 재시도로 이어간다. 지역 첫 요청 실패도 필터/지역 이동을 유지하고 같은 쿼리를 다시 요청한다. 초기화는 필터 키만 지워 다른 쿼리를 보존한다. [공통 필터](../../src/components/festival/FestivalFilters.tsx), [날짜 규칙](../../src/utils/festivalFilters.ts), [검색 훅](../../src/hooks/useSearch.ts)을 기준으로 한다.

## 내 리뷰와 프로필

[내 리뷰 미리보기](../../src/pages/My/components/MyPageOwnReviewPreviews.tsx)는 기존 getMyReviews를 호출한다. 제목이 같아도 축제 ID를 추정해서 연결하지 않고 리뷰 ID로 수정 화면을 연다. `myReviews/preview/5` 캐시를 분리하고 기존 myReviews 무효화 prefix를 유지한다. staleTime0으로 작성/수정 후 돌아왔을 때 새 내용을 읽는다. `?tab=reviewed`로 리뷰 탭을 직접 열고 수정 후 뒤로 가도 같은 탭을 유지한다.

프로필 모달·업로드·권한·로그아웃·탈퇴 핸들러는 원래 동작을 유지한다. 목 앱의 변경 요청은 읽기 전용 안내를 반환하며 실제 OAuth·저장·업로드·STOMP 전송은 하지 않는다. 일반 사용 앱의 인증 경계와 목의 샘플 계정을 구분한다.

## 검증

- typecheck·lint·test·build 통과. 프런트엔드24개 파일178개, Node 검사5개 통과.
- 린트 오류0, 큰 스냅샷 경고2개. 빌드의 단일 청크500kB 초과 경고는 남아 있다.
- VITE_ENABLE_MSW=true로 빌드해도 목 인증·메뉴·핸들러·목 사진이 제품 산출물에 포함되지 않음을 확인했다. production/mock/development의 build 명령 모두 목 별칭을 사용하지 않는다. 생성된 비교 설정 자체도 build를 거부한다.
- 검색/지역의 뒤 페이지에서만 발견되는 일치, 오류 후 기존 결과 유지·재시도, 기간 양 끝·잘못된 날짜, URL 보존, 리뷰 ID/캐시/탭 복귀, 프로필 모달 열기·포커스 복귀를 회귀 테스트로 확인했다.
- 별도 전체 소스 리뷰는 Critical0/Important0/Minor1이었다. 첫 지역 조회 실패 복구를 RED→GREEN으로 보완하고 전체 검사를 통과했다. 재리뷰는 하지 않았다.
- 이번 혼합안의12개 실제 Headless Chrome 캡처는320/375px에서 경로·내용·폭·원시 해시를 검증했다. 접근성 진단은 모두100점, 페이지 가로 넘침은 없었다. 짧게 표시한 채팅 이름/전체 접근성 이름에는 수동 label 검토 안내가 남는다.
- [작은 결과 JSON](../metrics/2026-11-13-hybrid-ui.json)에 원시 리포트 해시·조건·URL·시각을 보존한다. raw/PNG는 Git에서 제외한 superpowers/comparison/reports·screens에 로컬 보존했다.

대표 캡처는 hybrid-mock-home-375.png, hybrid-search-375.png, hybrid-browse-375.png, hybrid-mock-my-reviews-375.png, hybrid-settings-320.png다. 비교 페이지의 최종 열은 hybrid-compare-\* 캡처만 연결해 이전 독립안 이미지와 혼동하지 않는다.

실기기 키보드·실제 OAuth/S3/STOMP·실제 서버 권한은 인증하지 않았다. 이번 진단은 개발 서버 접근성/레이아웃 검사이며 production 성능 점수·LCP·INP나 WCAG 전체 준수 판정이 아니다. 의존성 버전과 기존 보안/번들 과제는 별도이며 이번에 변경하지 않았다. 계획과 작업 기록은 로컬에만 두고 디자인/검증 필수 문서만 추적한다.
